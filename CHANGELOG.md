## [Unreleased]

### Changed

- Normalize the LICENSE copyright holder to `Marek Cingel`, matching the source headers and every other OpenTLV repository. (#6)
- Install the OpenTLV Lua package under test from luarocks.org with `luarocks` in every setup, verifying the downloaded source rock, built Core commit and installed files against the pin. External libraries remain cached. (#4)

### Fixed

- Make the Rust differential CI job check exact, source-audited reference divergences instead of failing permanently on the six already reproduced differences. Preserve the standards runner's mismatch outcomes and exit code; reject new or changed observations, Core regressions, stale baseline entries and setup failures. (#30)
- Give the OpenTLV DER adapter the Tree Writer capacity that the BER and CER adapter already has, so DER values longer than 1024 bytes are encoded instead of failing with a buffer error. (#23)
- Correct the DER guide and the asn1c typed values, which said that asn1c reports OBJECT IDENTIFIER arcs above 2^32-1 as `null`; it reduces them modulo 2^32. (#23)
- Correct the capability check count, a broken dependency-setup link and the verification notes that still described hosted Fast and Extended as pending. (#8)

### Added

- Extend the BER/DER runner to Core v0.8.0, published opentlv/opentlv-sys 0.2.2 and der-parser 10.0.0, with fresh verified Rust crate acquisition, public-facade probes, native error locations and exact three-participant regression observations. Add a source-backed capability/gap audit linked to Rust #50, #51 and #52 under #46; keep missing APIs open and separate from fixture agreement. (#31)
- Deterministic Core v0.8.0 versus der-parser 10.0.0 BER/DER runner over the reviewed Rust corpus, with fresh verified Core source acquisition, bounded native adapters, normalized observations, independent X.690 verdicts, reproducible JSON/Markdown reports and coverage denominators. Add Fast CI with verified external Cargo caching, agreement/mismatch/setup-failure probes and report uploads. Preserve shared mismatches as failing outcomes and keep Rust binding execution separate. (#30)
- Rust BER/DER reference baseline: pin der-parser 10.0.0 and its complete Cargo dependency graph, record registry/archive/license/MSRV provenance, audit the external APIs, and define a reviewed fixture corpus, capability matrix and normalized observation schema. Separate BER decoding from strict DER validation and preserve unsupported/inconclusive cases. The differential runner and Rust binding comparison remain separate follow-up work. (#29)
- Differential fuzzing: `scripts/run_fuzz.py` generates typed values and mutated BER, DER and CER encodings, feeds the same input to OpenTLV Lua v0.3.0 and the asn1c reference, and judges both against the X.690 reference. `scripts/x690.py` gains a DER profile and rule profiles that model what OpenTLV Lua implements, so a documented gap is never mistaken for a defect. Every case derives from a seed, through a generator that gives the same case on every platform, and can be rerun alone. A difference that a documented limitation or capability probe explains is classified as such. Any other is a semantic or canonical mismatch, crash or sanitizer report: it is minimized, rechecked against X.690 and kept locally, with reproduction commands and a draft fixture for the committed corpus. `setup_asn1c.py --sanitize` builds the asn1c adapter with AddressSanitizer and UndefinedBehaviorSanitizer, leaving out only the check that a benign zero-length copy in asn1c's runtime trips. The fuzzer refuses public CI and output in the tracked tree, Fast runs only its unit tests, and `docs/differential-fuzzing.md` documents the feature intersection, triage and disclosure policy. Three new asn1c capability probes record what fuzzing found: arcs above 2^32-1 are reduced modulo 2^32, a BIT STRING segment without its initial octet is ignored, and an empty constructed BIT STRING is rejected. No OpenTLV defect was found. (#23)

- BER and CER differential: `scripts/run_ber_cer_differential.py` decodes and encodes 154 hand-written fixtures, 99 BER and 55 CER, with OpenTLV Lua v0.3.0 and the asn1c reference, and judges each library against X.690. A new independent reference, `scripts/x690.py`, validates every fixture and reads BER encoders' output by logical value, so BER bytes are never required to match. CER is compared byte for byte for one type and value. Fixtures cover high tags, definite, indefinite and alternative lengths, end-of-contents, constructed, nested and segmented strings, alternate BER forms, CER canonical forms and segmentation, truncation and malformed input, and 62 reuse the bytes of the #1 and #21 corpora. Each check is classified as pass, mismatch, confirmed, limitation, not comparable or inconclusive, with cited reasons, and reports give per-encoding coverage with denominators. No OpenTLV defect was found. Six new asn1c capability probes record its constructed-string, explicit-tag, BIT STRING and OBJECT IDENTIFIER deviations. A separate Fast job runs the corpus and a deliberate mismatch probe, `check_report.py` reruns its reports, and `docs/ber-cer-differential.md` documents the checks, corpus, results and limits. (#22)
- DER canonical differential: `scripts/run_der_differential.py` decodes and encodes 98 hand-written fixtures with OpenTLV Lua v0.3.0 and the asn1c reference, and judges each library against X.690 instead of trusting either. Fixtures cover high tag numbers, short and long length boundaries, zero-length, primitive, constructed and nested values, and noncanonical and malformed variants. Encoders are compared byte for byte only for the same type and value, and each library decodes the other's encoding. Errors are normalized to `empty`, `truncated`, `trailing` and `invalid`, and asn1c's DER verdict requires its canonical re-encoding. A fixture declares what a library cannot decide, citing documentation or a capability probe, and a limitation that no longer shows fails the run. Reports give the outcome matrix, coverage denominators, every observation and per-fixture reproduction. No OpenTLV defect was found. A separate Fast job runs the corpus and a deliberate mismatch probe, `check_report.py` now also reruns DER reports, and `docs/der-differential.md` documents the checks, corpus, limitations and results. (#21)
- Optional asn1c reference adapter: `scripts/setup_asn1c.py` builds `vlm/asn1c` v0.9.29 from its digest-pinned release archive into an exact-key cache, generates the versioned `TestLabReference-1` schema twice to require deterministic output, and compiles the generated code with a C adapter that returns normalized typed values, DER re-encodings and error categories. 71 committed probes classify BER decoding, DER decoding and encoding and CER as supported, unsupported or not comparable, and setup and `scripts/check_asn1c.py` fail on any changed observation. A separate Fast job runs it; `docs/asn1c-reference.md` records the pin, provenance, license, alternatives, contract and findings. No OpenTLV dependency or Core option is added. (#20)
- Contributor documentation: the README now takes a contributor from installation to a reproduced comparison, and covers the commands, supported BER subset, fixture contribution, result interpretation, version and cache policy, CI and limits. The guides add step-by-step fixture and pin-change procedures, and a new test checks documented links, commands, the fixture example and corpus totals. (#8)
- Manual `Extended` workflow and `scripts/run_extended.py`: on x86-64 and arm64 Ubuntu it runs a cold and a repeated setup, an offline cache check, the standalone capability audit, both corpora with repeat and second-install comparisons and the mismatch probe, and uploads a summary, reports, provenance and logs. Fast stays the pull request gate, and Extended otherwise runs only on pull requests that change the suite. Document both in `docs/ci.md`. (#7)
- Actionable differential reports: input bytes, operation, schema, expectation, both libraries' outputs and errors, runtime, package versions, TestLab commit and per-failure reproduction commands, with possible defects kept apart from declared unsupported or inconclusive fixtures. Run failures also write a report naming any failing input. Add `--report` and `--fixture`, upload reports from Fast, and require the deliberate mismatch probe's report to reproduce itself. (#6)
- Deterministic ASN.1 BER differential corpus of primitive, constructed, nested, tag and length boundary, truncated and malformed cases, with a declared support classification, category, description and pin-checked reproduction metadata. Fast runs it through both adapters, and the capability audit gains the probes that its reasons cite. (#5)
- Lua differential runner with independent OpenTLV Lua and lua-asn1 adapters over the same bytes, normalized parse trees and values, and pass/mismatch/unsupported/inconclusive outcomes. Crashes, timeouts, resource limits and changed dependencies are run failures, and Fast runs seed fixtures and a deliberate real-library mismatch probe. (#4)
- Reproducible Lua dependency setup using lua-asn1's upstream Makefile, an integrity-checked cache keyed by source/runtime/platform/configuration, and fresh OpenTLV Lua v0.3.0 source-rock installation with package provenance. Extend Fast CI with cache-policy tests, installed-library checks and setup logs. (#3)
- Pin `kunkku/lua-asn1` v2.2.1 by commit and source hashes; document its MIT license, Lua runtime requirements and concrete BER comparison matrix against OpenTLV Lua, including unsupported features and known upstream differences. Add an executable capability audit and initial Fast CI gate. (#2)
